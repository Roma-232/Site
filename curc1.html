1
Введение в кибербезопасность и основы безопасности ОС
6 часов

Теория недели

1. Кибербезопасность: что это и зачем?

Контекст: от домашнего роутера до корпоративной сети. Основные цели: защита данных, систем, репутации, финансов.

2. Триада CIA (Конфиденциальность, Целостность, Доступность):

  • Конфиденциальность (Confidentiality): Данные доступны только авторизованным субъектам. Угрозы: утечка, подслушивание. Защита: шифрование, контроль доступа.
  • Целостность (Integrity): Гарантия, что данные не были изменены несанкционированно. Угрозы: модификация, подделка. Защита: хеши, цифровые подписи.
  • Доступность (Availability): Системы и данные доступны, когда это необходимо. Угрозы: DDoS-атаки, отказ оборудования. Защита: резервирование, балансировка нагрузки.

Пример: Интернет-банк. Конфиденциальность = пароль, Целостность = сумма перевода не изменена, Доступность = сайт работает 24/7.

3. Основные концепции:

Уязвимость (Vulnerability), Угроза (Threat), Атака (Attack), Риск (Risk). Простая формула: Угроза + Уязвимость = Риск реализации Атаки.

4. Безопасность на уровне операционных систем (Windows):

  • Пользователи и группы: Принцип наименьших привилегий. Встроенные группы (Администраторы, Пользователи, Гости).
  • Разрешения NTFS: Чтение, Запись, Выполнение, Полный доступ. Наследование разрешений.
  • Управление процессами и службами: Какие процессы должны работать? Какие службы запущены и от чьего имени?

5. Журналы событий Windows (Event Viewer):

Где искать следы? Категории логов (Security, System, Application). Ключевые идентификаторы событий (Event ID):

C:\> Ключевые Event IDs:
4624 — Успешный вход
4625 — Неудачная попытка входа
4688 — Создание нового процесса
7045 — Установка службы

Практическое задание №1: Аудит рабочей станции

Среда:

Предоставляется доступ к удаленной виртуальной машине с Windows Server.

Задание:

  1. Создать нового пользователя с минимальными привилегиями, назначить пароль по политике (мин. 8 символов, сложность).
  2. Провести инвентаризацию: выписать все запущенные службы, отсортировать их по "имени входа". Найти службы, работающие от имени SYSTEM.
  3. Проанализировать журнал Security за последний час. Найти все события 4625 (неудачный вход). Определить, с какого IP-адреса и на какую учетную запись были атаки.
  4. Создать простой файл, настроить на него разрешения NTFS: полный доступ для Администраторов, чтение для Пользователей.

Итог:

Отчет в формате "Заметки аудитора" с выводами о базовой безопасности системы.

Ключевые термины недели

CIA Triad • Уязвимость • Угроза • Риск • NTFS • Event Viewer • Event ID • Принцип наименьших привилегий

Security Tip

Всегда проверяйте журналы событий после любых подозрительных активностей. Event ID 4625 может указывать на попытку брутфорса паролей к вашей системе.

Основы компьютерных сетей. Модель OSI/TCP-IP
8 часов

Теория недели

1. Зачем security-специалисту сети?

Понимать путь данных = уметь его защищать, контролировать и расследовать инциденты.

2. Модель OSI 7 уровней и стек TCP/IP:

  • Уровень 3: Сетевой (IP, ICMP). IP-адресация (IPv4), маски подсети, шлюзы. ICMP — пинг, трассировка.
  • Уровень 4: Транспортный (TCP, UDP).
    • TCP: Установка соединения (three-way handshake: SYN, SYN-ACK, ACK), гарантированная доставка. Порты — "двери" для служб (80-HTTP, 443-HTTPS, 22-SSH, 3389-RDP).
    • UDP: Бессоединный, быстрый, без гарантий. Пример: DNS, видеостриминг.
  • Уровень 7: Прикладной (HTTP/HTTPS, DNS, DHCP, SMTP).

3. Ключевые протоколы с точки зрения безопасности:

  • DNS: Преобразование доменных имен в IP. Уязвимость к спуфингу и отравлению кэша.
  • HTTP/HTTPS: Чем отличается безопасный протокол (шифрование TLS/SSL). Понятие сертификатов.
  • ARP: Протокол разрешения адресов в локальной сети. Уязвимость к ARP-спуфингу.

Практическое задание №2: Сетевой разведчик

Инструменты:

Командная строка (Windows cmd/powershell или Linux bash), простой сетевой анализатор.

Задание:

  1. Используя ipconfig / ifconfig, определить свой IP-адрес, шлюз, маску подсети и DNS-сервер.
  2. С помощью ping и tracert построить путь до нескольких сайтов (google.com, ya.ru). Проанализировать хопы.
  3. С помощью netstat -an вывести список всех активных сетевых подключений. Определить, какие порты слушают (LISTENING), а какие установлены (ESTABLISHED).
  4. Анализ заранее записанного Pcap-файла в Wireshark: Ответить на вопросы: Какой IP-адрес атакует? На какой порт? Какой протокол используется?

Итог:

Заполненный "лабораторный журнал" с ответами на вопросы и скриншотами.
